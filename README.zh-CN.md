# dsh-prompt-upgrade（提示词升级）

把输入框里随手写下的一句话，一键重写成结构清晰、可直接执行的提示词：**先预览、再回填、随时撤销**，原草稿永不被动修改。

> **这不是官方插件。** 本仓库 fork 自 [`rongxingda/dsh-prompt-enhance`](https://github.com/rongxingda/dsh-prompt-enhance) v0.3.4（Apache-2.0），本次 fork 改名为 `dsh-prompt-upgrade`，主要变化是**补上了上游缺失的设置面板**（上游 0.3.x 的设置只存在于 schema 里，DSH 0.2.x 移除「设置 → 插件配置」页后没有任何界面渲染它）。
> 需要向 DSH 官方反馈问题时，请回到上游仓库；本仓库的问题属于本改造。

---

## 这插件是给谁用的

- 你在 DSH Web GUI 里**经常写长提示词**，希望它自动补上目标、约束、输出格式；
- 你想让重写**跟随当前会话的模型**，或反过来钉死某个便宜模型；
- 你要**成本可控**：能看见每次重写花了多少 token、能限流、能关掉。

不适合：纯 CLI 场景（浏览器半边不加载）、想用它替代人工设计提示词（它只做结构化重写，不替你决定做什么）。

## 安装

从 npm 安装（推荐）：

```powershell
dsh plugin --profile web add dsh-prompt-upgrade
```

跟随 GitHub 主干（未发版的最新提交）：

```powershell
dsh plugin --profile web add github:yiyunet/dsh-prompt-upgrade
```

从本地克隆链接（改插件时用，路径按你自己的来）：

```powershell
git clone https://github.com/yiyunet/dsh-prompt-upgrade.git
dsh plugin --profile web add link:./dsh-prompt-upgrade
```

装完**刷新一次浏览器页面**。客户端半边（按钮/面板）随页面加载，宿主半边（路由/命令）随 `dsh web` 进程加载。

**不要与 `dsh-prompt-enhance` 同时启用**：两者注册同一组槽位与路由形态，且 `prompt-enhance` / `prompt-upgrade` 是两份独立的设置文档。要换用本插件，先卸载上游那份。

### 怎么确认装上了

1. 输入框右下角出现「提示词增强」按钮 → 客户端半生效；
2. 「设置 → ANB 工具 → 提示词升级」出现面板 → 设置半生效；
3. 输入 `/enhance` 能看到命令 → 宿主半生效。

三条缺哪条，看文末「故障排查」。

## 设置在哪（重点）

**设置 → ANB 工具 → 提示词升级**。

面板挂在「ANB 工具」壳里（不是自己开一个设置导航项），所以设置里只有「ANB 工具」一个入口，里面按插件分成一行行标签。多个插件共用同一个壳，任一在场即显示。

面板里改完点**保存**才写入；没保存就切走，草稿自动丢弃。

## 18 个设置项

分三组，区间与宿主校验一致——填错会在字段上标红并**阻止保存**，而不是存进去再被驳回。

### 基础

| 设置项 | 默认 | 说明 |
|---|---|---|
| 启用提示词增强 | 开 | 关掉后隐藏按钮、停用快捷键与所有触发方式 |
| 快捷键 | `ctrl+alt+e` | 必须含 ctrl / alt / meta 至少一个（shift 只能附加）；留空禁用 |
| 增量显示 | 开 | 模型边写边显示。**只影响显示节奏**，最终回填文本不变 |
| 上下文感知 | 开 | 读取当前会话近期对话来消解指代；无历史时自动回退为单条增强 |
| 自定义提示词的组合方式 | `replace-default` | `replace-default` 整体替换内置策略（内置硬性约束不再保留）；`extend-default` 追加在内置策略之后，硬性约束继续生效 |
| 自定义系统提示词 | 空 | 留空用内置策略；多行文本 |

### 成本与性能

| 设置项 | 默认 | 区间 | 说明 |
|---|---|---|---|
| 推理预算 | `off` | off/low/high/inherit | 改写是短任务，`off` 最省；`inherit` = 不传该字段、跟随模型默认档。实测同一句话：`off` 约 252 输出 token，`high` 约 2897 |
| 采样温度 | 0.3 | 0–1（可小数） | 低温更忠实于原意 |
| 输出 token 上限 | 8192 | 256–32768 | 单次重写的输出上限 |
| 输入字数上限 | 12000 | 200–200000 | **超限拒绝而不截断**（截断会改变原意） |
| 超时（毫秒） | 60000 | 5000–600000 | 端到端时限 |
| 并发上限 | 2 | 1–16 | 超出的请求返回 429 |
| 每分钟次数上限 | 10 | 1–600 | 滑动窗口；超出返回 429 并给 `Retry-After` |

### 模型路由与上下文

| 设置项 | 默认 | 区间 | 说明 |
|---|---|---|---|
| provider 覆盖 | 空 | — | 留空跟随当前会话模型；**一旦填写必须与 model 成对**，否则保存被拒 |
| model 覆盖 | 空 | — | 同上，必须与 provider 成对 |
| 上下文窗口（条数） | 8 | 0–50 | 最多参考最近多少条 user/assistant 轮次；0 = 不参考 |
| 上下文窗口（字数） | 4000 | 0–100000 | 历史片段的字符预算，从最新一条向前装配；0 = 不参考 |

## 用一次（完整流程）

1. 在输入框写一句话，例如「帮我写个排查 HKV 风机的提示词」；
2. 点输入框旁「提示词增强」按钮，或按 `ctrl+alt+e`；
3. 面板左边是你**原文**，右边是**重写结果**（可边写边看）；
4. 判断结果：够了就点「回填到输入框」，不满意点「重试」或直接关掉——**原草稿一直没变**；
5. 回填后底部出现撤销条，点「撤销」回到回填前那一版（即使你在回填后又改过字，撤销也是回到回填前）。

失败时看面板上的红字：空输入、超长、含命令/文件引用、被禁用、超时、上游鉴权/配额/限流各不相同，按提示处理即可，**原文不会因此被改**。

## 数据后果（重要）

- **设置存在哪**：DSH 的设置文档，命名空间 `prompt-upgrade`（与本插件包名不同，这是有意的：包名可改，命名空间一旦改就会丢配置）。
- **旧的 `prompt-enhance` 配置不会继承**。若你之前在上游插件里写过设置，需在本面板重填一次。上游那份若还在用，两边互不影响。
- **不联网不写远端**：重写只调用你已在 DSH 里配好的模型服务；本插件不上报任何内容、不落盘草稿。
- **草稿只在内存**：关页面即丢，不写历史。

## 卸载与回滚

```powershell
dsh plugin --profile web remove dsh-prompt-upgrade
```

设置文档留在本地（重新装回来还在）。若要把工作区改动整体退回上游原状（在仓库目录内执行）：

```powershell
git checkout -- .
```

## 故障排查

| 现象 | 检查什么 |
|---|---|
| 设置里没有「ANB 工具」 | 是否有**其它** ANB 插件已注册壳（壳是单例，任一在即出现）；确认客户端半加载：刷新页面后看控制台有无 `[prompt-upgrade]` 开头的告警 |
| 有「ANB 工具」但没有「提示词升级」标签 | 宿主没暴露 `prompt-upgrade` 命名空间：确认 `dsh web` 进程加载了本插件（宿主半），且没被 `disabled` |
| 面板能开但全是灰的 | 设置文档只读（部署级），或命名空间未就绪时的占位 |
| 保存后行为没变 | 本插件**每次请求都重读**设置，保存即生效；若没变，先确认保存按钮真的成功了（有没有红色失败提示） |
| 按钮不出现 | 面板里「启用提示词增强」是否被关掉；或输入框正被占用（提交中） |
| 按快捷键没反应 | 快捷键是否含修饰键、是否与宿主/其它插件撞键（本插件在总开关关闭时**不抢键**） |

## 开发

```powershell
git clone https://github.com/yiyunet/dsh-prompt-upgrade.git
cd dsh-prompt-upgrade
npm ci
npm run typecheck
npm test        # 270 个用例
npm run build   # lib/index.js（宿主）+ lib/client.js（浏览器）
```

**改动前请检查壳块一致性**：面板挂在多个插件共用的「ANB 工具」壳里，而壳块在 `src/client/anb-shell.mjs` 中是**逐字节内联**的。同一块壳在多个插件里必须完全一致，否则会出现「壳闪一下又消失」「侧栏两个 ANB 工具」「标签行出不来」这类运行时症状，且很难归因。

检查方法是把 `// >>> ANB-SHELL:BEGIN v2` 与 `// <<< ANB-SHELL:END v2` 之间的内容，与同族插件逐行比对（剥离公共缩进后），两件事都要看：① 壳块是否逐字相同；② 有客户端半边的插件是否漏挂了壳。

该比对脚本属于发布方的内部工具，不随本包分发。

### 代码地图

| 文件 | 职责 |
|---|---|
| `src/index.ts` | 宿主半：装设置源、挂路由、注册 `/enhance` 命令 |
| `src/config.ts` | 18 字段 schemastery schema（**每字段 `.volatile()` 不可删**：无 volatile 字段的条目会被宿主整条丢弃） |
| `src/enhance-routes.ts` / `src/enhancer.ts` | HTTP 路由与模型调用（限流、并发、超时、SSE） |
| `src/client/index.tsx` | 浏览器半：按钮/撤销条槽位、设置镜像、快捷键、**设置面板挂载** |
| `src/client/settings-form.ts` | 面板的暂存层：草稿、脏值/非法判定、保存动作。持久化与 revision 围栏归宿主 |
| `src/client/PromptUpgradeSettings.tsx` | 面板组件（自绘控件，零新增运行时依赖） |
| `src/client/anb-shell.mjs` | 「ANB 工具」壳（**逐字节复制**，勿改） |
| `src/client/styles.ts` | 自注入样式表（前缀 `dsh-pe-`） |

### 为什么不用官方的 `SettingsFormModel`

`@deepseek-ai/dsh-client-ui-primitives` 的 `lib` 产物带 CSS module 导入，且依赖树未完整声明（`clsx`、`@deepseek-ai/dsh-util-workspace-path`），在插件自己的构建/测试链里不可靠。本插件因此只对齐宿主的**契约**（`configForms.get() → {getSnapshot, subscribe, mutate}`），暂存层自研约 120 行。宿主侧的行为（revision 围栏、写后回读恢复）没有重写。
